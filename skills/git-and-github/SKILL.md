# Git & GitHub

## Ground Rules

- Never credit the agent: no `Co-Authored-By` trailer and no "generated by" attribution in commit
  messages or pull request descriptions.
- Never commit on `main`, `master`, or the default branch: create a feature branch first and work
  there.
- Confirm scope before staging: inspect `git status -sb` and the diff. In a mixed worktree stage
  explicit paths and ask which files belong; use `git add -A` only after the user confirms the whole
  worktree is in scope.

## Commits

- One logical change per commit with a conventional-commit subject: `feat:`, `fix:`, `chore:`,
  `refactor:`, `test:`, `docs:`.
- Squash throwaway "wip" commits before opening a pull request.
- Run the most relevant checks before pushing if they have not already been run.

## Push

- Push with git over SSH: `git push -u origin $(git branch --show-current)`.
- When authentication is not granted (`Permission denied (publickey)`, missing SSH key, or no remote
  access), stop and tell the user exactly what is missing; do not retry blindly or switch the remote
  to HTTPS as a workaround.

## Pull Requests

- Verify `gh auth status` first; when unauthenticated, ask the user to run `gh auth login` and stop.
- Default to a draft PR unless the user asks for ready-for-review; base it on the remote default
  branch (`gh repo view --json defaultBranchRef`) unless the user names another base.
- Create with `gh pr create --draft --fill --head $(git branch --show-current)`; write a custom body
  to a temp file with real newlines so the Markdown renders cleanly.
- Keep the description compact: what changed and why in a few lines, the user or developer impact,
  the root cause when the PR is a fix, and the checks used to validate it. For visual changes
  include screenshots or before/after examples. No filler.
- When the repository has no accessible GitHub remote, stop and explain the blocker before making
  assumptions.
