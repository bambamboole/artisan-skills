# Git & GitHub

## Model, Scope, and Branch

- When supported, delegate routine, well-scoped work to a small, fast subagent model at low effort.
  Keep ambiguous scope, conflicts, history rewrites, releases, and recovery with the primary agent;
  model choice never expands authorization.
- Never credit the agent: no `Co-Authored-By` or "generated by" attribution.
- Inspect status, diff, and branches before staging. Preserve unrelated work; stage explicit paths
  and use `git add -A` only for a confirmed whole-worktree scope.
- Never commit on `main`, `master`, or the default branch. Create a feature branch first.

## Commit and Push

- Make one logical change per conventional-commit subject.
- Squash throwaway "wip" commits and run the relevant checks before pushing.
- Push the current branch through the repository's configured SSH remote. If authentication or
  access fails, stop and identify what is missing; do not retry blindly or switch to HTTPS.

## Pull Requests

- Verify `gh auth status`; if unauthenticated, ask the user to run `gh auth login` and stop.
- Honor a named base or use the remote default branch. Open a draft unless the user requests
  ready-for-review.
- Keep the body compact: change and reason, impact, a fix's root cause, and verification. Include
  before/after evidence for visual changes.
- After creation, read the PR back through GitHub and verify its base, head, title, body, and state;
  return its URL. If no GitHub remote is accessible, stop and explain the blocker.
